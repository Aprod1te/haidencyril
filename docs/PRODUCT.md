# 产品说明

## 产品目标

Haidencyril 不是另一个笔记编辑器。它是 Obsidian 之上的个人工作流层，帮助用户完成：

```text
随手记录 → 找回记忆 → 发现联系 → 共同分析 → 形成项目 → 安排行动 → 复盘结果
```

产品成功不以“生成多少内容”衡量，而以用户是否更容易持续记录、看清问题并完成真实行动衡量。

## 核心用户

- 单一用户，全部设备处于苹果生态。
- 经常携带 MacBook 和 iPhone，希望改变随手记录习惯。
- 输入包括个人想法、活动策划案、执行中发现的问题、模糊反馈和行动结果。
- 个人数据不公开，只公开程序代码。

## 思考保护原则

系统应当自动完成捕捉、索引、候选联系和信息归纳，但不能替用户完成价值判断。

分析界面必须明确区分：

- 原文直接支持的事实。
- 系统提出的解释或根因假设。
- 目前缺失的信息。
- 支持与反对某个解释的依据。
- 系统希望用户亲自回答的问题。

系统不展示或声称展示模型隐藏的内部思维过程，而是提供一份可以被用户检查和反驳的“分析账本”。

## 0.1 范围

### 已实现

- 无需分类的碎片捕捉。
- 移动端兼容的 Obsidian 工作台。
- 收件箱状态概览。
- 工作台关键词搜索和处理状态筛选。
- 本地候选笔记粗筛。
- 分析前先记录用户自己的初步判断与不确定点。
- 用户主动触发的结构化 AI 分析。
- 将用户判断与系统分析进行支持、冲突和未知项对照。
- 分析历史独立保存，原文只增加 namespaced 元数据。

### 下一阶段

- 苹果快捷指令捕捉：听写、截图、照片、网页分享。
- 可重建的本地语义索引和语义搜索。
- 将一组碎片提升为项目。
- 项目目标、风险、验证事项和下一步行动。

### 后续阶段

- 从教务系统登录后的导出内容、课表文件或截图导入课程。
- 临时补课通知进入统一收件箱。
- 生成日程草案，并通过快捷指令写入苹果日历和提醒事项。
- 固定课程、强制活动、可移动工作块之间的冲突求解。
- 项目复盘与长期主题演化。

## 日程决策规则

- 考试和明确不可缺席的活动属于绝对固定时间。
- 课程默认受到保护。
- 高优先级任务可以建议占用课程时间，但必须再次说明代价并获得确认。
- 工作块默认可移动，发生冲突时先寻找替代时间。
- 所有截止日期、提醒和日历事件在写入前都要显示确认内容。

## 明确不做

- 自建 Markdown 编辑器。
- 自有账户和同步系统。
- 在没有明确收益前部署常开服务器。
- 保存教务系统账号密码或绕过登录权限。
- 在第一版引入向量数据库、工作流引擎或通用代理框架。
- 将 AI 推断伪装成事实。
