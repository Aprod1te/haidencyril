# 架构决策

## 总览

```text
Apple 快捷指令 / Obsidian 捕捉
                ↓
        Markdown 收件箱（事实来源）
                ↓
      本地候选检索（可重建派生数据）
                ↓
  用户主动触发 Ollama 本地结构化分析
                ↓
       Markdown 分析账本（可追溯）
                ↓
     主题 / 项目 / 行动 / 日程草案
```

## ADR-001：作为 Obsidian 插件构建

**决定：** 替换原有展示型 Vite 网站，基于 Obsidian 官方插件模板开发。

**理由：** Obsidian 已经解决 Markdown 编辑、链接、反向链接、图谱、附件、移动端和插件生态等成熟问题。本项目只实现尚缺少的工作流层。

**后果：** 第一版不提供独立网页。插件使用 TypeScript、esbuild 和 Obsidian API，并保持 `isDesktopOnly: false`。

## ADR-002：Markdown 是事实来源

**决定：** 原始碎片、分析账本和未来项目都保存为用户可直接阅读的 Markdown 文件。

**理由：** 数据不会被应用锁定，离开插件后仍然可以搜索、编辑和迁移。

**约束：** 插件元数据统一使用 `haidencyril_` 前缀。AI 分析不覆盖原文；重新分析会生成一份新的账本，历史关系由 Markdown 链接和反向链接保存，不在属性中重复保存文件路径。

## ADR-003：派生索引可删除并重建

**决定：** 语义向量、关键词索引和聚类结果未来都属于缓存，不成为事实来源。

**理由：** 避免数据库损坏或模型升级导致知识库不可用。个人规模使用本地 JSON 语义索引和内存余弦检索，不引入向量数据库。

## ADR-004：AI 是显式、可审计的本地处理器

**决定：** 使用 Ollama 在 Mac 本地运行 Qwen3.5。9B 模型负责深度分析，4B 模型负责短任务拆解；用户先写下自己的判断，再主动生成对照分析。输出由 JSON Schema 约束并由 Zod 再次验证。

**理由：** 固定结构可以可靠地区分事实、假设、未知和问题，也能在模型输出异常时拒绝写入。

**安全边界：** 请求只发送到 `127.0.0.1` 的 Ollama 服务，不需要 API Key。候选联系返回后再次按本地路径白名单过滤。

## ADR-005：移动端优先使用 Obsidian 抽象

**决定：** 不使用 Node.js `fs`、Electron 或桌面绝对路径；文件访问使用 Vault API，网络访问使用 `requestUrl`。

**理由：** 同一份插件代码需要运行于 macOS、iPhone 和 iPad。记录、浏览和同步保持跨端；AI 分析只在运行 Ollama 的 Mac 上可用。

## ADR-006：苹果原生能力通过快捷指令桥接

**决定：** 捕捉、日历只读同步、日历写入和提醒事项写入优先通过苹果快捷指令实现，不先开发原生 iOS 扩展。

**理由：** 快捷指令已经提供听写、分享表单、OCR、日历和提醒事项动作，是成本最低且稳定的系统集成方式。

**边界：** 同步快捷指令只交付未来八天的只读快照；插件只生成待确认的日程或提醒记录；写入快捷指令负责在用户确认后新增系统日历事件或提醒事项。

## ADR-007：教务系统采用导入适配器

**决定：** 不在插件中保存账号密码。用户登录教务系统后，插件处理导出的文件、页面内容或截图。

**理由：** 教务系统可能存在旧式登录、验证码和页面变化。导入适配器比自动登录更安全，也便于以后替换数据源。

## ADR-008：项目是链接碎片的独立 Markdown

**决定：** 项目保存在 Projects 目录，以原生链接引用来源碎片，并在正文中维护目标、完成标准、风险、待验证事项和下一步行动。

**理由：** 项目是用户对若干事实和判断作出的行动承诺，不应覆盖或搬迁原始碎片。单向写入项目链接已经能通过 Obsidian 反向链接形成可追溯关系，也避免在多份碎片中复制项目路径。

**边界：** 创建项目不会自动安排日期。截止时间和日程仍在后续确认流程中单独处理。

## ADR-009：语义检索使用本地可重建 JSON 缓存

**决定：** 使用 Ollama `/api/embed` 和轻量 `qwen3-embedding:0.6b`，索引保存在插件目录的 `semantic-index.json`。文件修改后按 `mtime` 增量重建，不引入向量数据库。

**理由：** 个人 Vault 规模下，内存余弦检索足够简单可靠。索引不属于事实来源，删除后会从 Markdown 自动恢复。

## ADR-010：课程与日程使用开放格式和确认账本

**决定：** 工作台合并苹果快捷指令提供的日历快照、`ical.js` 解析的 RFC 5545 `.ics` 文件及已确认行动。快照、导入结果、日程草案和冲突确认都保存为 Markdown；最终写入苹果日历由快捷指令完成。

**理由：** iCalendar 和 Shortcuts 是苹果生态内经过验证的互操作边界。插件无需日历权限、账号系统或常开服务器，也不会保存教务系统凭证。

## ADR-011：任务拆解保存在来源笔记中

**决定：** 本地模型把零碎事项整理为最多八个有顺序的行动和可观察的完成标准；用户可以直接修改后，将清单作为标准 Markdown 待办写回当前笔记。每一步独立复用既有日程确认流程。

**理由：** 清单属于来源笔记的行动视图，不需要新增数据库、任务实体或工作流引擎。普通 Markdown 能被 Obsidian 原生搜索、编辑和同步；单项安排继续复用已有的课程保护、冲突检查与快捷指令写入边界。

**边界：** 模型不得编造日期。无法确定的前提先列为需要用户回答的问题，任何日历写入仍须用户确认。

## ADR-012：任务工作台只聚合 Markdown

**决定：** 工作台扫描“可执行任务清单”和项目“下一步行动”中的标准 Markdown 复选框。完成任务时，在原笔记追加实际结果、偏差和下次调整，不维护第二份任务数据库。

**理由：** 原笔记继续是唯一事实来源，Obsidian、移动端和其他插件都能读取同一状态，也避免同步时出现两份任务互相覆盖。

## 目录约定

默认 Vault 目录：

```text
Haidencyril/
├── Inbox/
├── Analysis/
├── Projects/
└── Schedule/
    ├── Courses/
    ├── Calendar/
    └── Drafts/
```

目录可在设置中修改。插件不会在加载时创建目录，只有第一次写入时才按需创建。
